---
title: 兼容性与故障排查
description: 诊断常见的 vgui 工具链、原生依赖、窗口和平台验证问题。
---

vgui 是实验性项目，跟随持续变化的 Rust nightly 和 Git 依赖。遇到失败时，先判断问题发生在依赖解析、编译、原生窗口创建还是浏览器行为阶段。

## 工具链与依赖变化

仓库选择 `nightly`，但没有固定日期，示例依赖也没有指定 Git 版本。因此，新安装可能解析出与之前构建不同的代码。

- 保留应用的 `Cargo.lock`，让依赖更新成为主动操作。
- 如果未锁定依赖的项目以前可用而现在失败，请对照完整的[快速开始](../quick-start/)检查清单和入口。
- 使用 `cargo +nightly check`，将编译问题与窗口运行时问题区分开。
- 不要认为针对另一个 GPUI 版本编写的示例仍使用相同的应用 API。

## 原生构建失败

根据错误中最先出现的缺失软件包、链接输入或构建脚本失败来定位问题。

| 症状 | 检查内容 |
| --- | --- |
| `pkg-config` 找不到软件包 | 安装 `pkg-config` 和该软件包的开发文件，而不只是运行时库。 |
| `bindgen`、Clang 或头文件错误 | 安装 `libclang`、C/C++ 构建工具链，以及安装页列出的开发头文件。 |
| 字体、GTK、X11、Wayland、GL、音频或 D-Bus 链接错误 | 将已安装的开发软件包与发行版对应清单比较。 |
| 首次构建耗时很长 | GPUI 和图形后端是大型原生依赖；后续构建会复用 Cargo 产物。 |

Debian/Ubuntu 软件包清单及 macOS/Windows 前置要求请返回[安装](../installation/)查看。其他发行版的软件包名称可能不同。

## 程序编译成功但没有窗口

成功构建不要求图形会话，但打开原生窗口需要图形会话。

- 请在桌面会话中运行应用，不要使用没有显示转发的无头 CI 或 SSH 环境。
- 在 Linux 上，检查进程是否能访问相关图形会话及 `DISPLAY` 或 `WAYLAND_DISPLAY` 环境。
- 检查终端中窗口创建或原生图形后端报告的错误。
- 不要将 Linux 上的结果视为 macOS 或 Windows 验证；每个平台都需要单独的运行和交互检查。

可以在仓库检出目录中编译检查计数器：

```bash
cargo check -p vgui --example counter --locked
```

该命令检查代码和依赖，不会打开窗口或点击按钮。

## WebAssembly 与浏览器问题

请分别回答以下问题：

1. 是否为选定的 nightly 工具链安装了 `wasm32-unknown-unknown`？
2. 这个具体应用是否为该 target 编译成功？
3. 生成的模块和资源是否已在浏览器中加载？
4. 是否实际测试了渲染、尺寸、键盘输入、文本输入、IME、剪贴板和无障碍行为？

前一步的“是”不表示下一步也成立。当前[原生与 Web](../native-and-web/)页面只说明已有支持代码，不宣称已有验证通过的浏览器计数器。

## 获取帮助

报告问题时，请提供操作系统、Rust 工具链、相关依赖版本、完整命令和第一段完整错误。运行时问题还应说明应用是否编译成功，以及窗口或浏览器 canvas 是否出现。

携带这些信息提交 [GitHub issue](https://github.com/vgerbot-libraries/vgui/issues)，或返回[快速开始](../quick-start/)对照一个最小项目。
