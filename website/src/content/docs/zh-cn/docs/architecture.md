---

vgui 将编译期视图宏、GPUI 元素和缓存在 slot 中的响应式状态组合在一起。最重要的边界很清晰：`view!` 描述元素，响应式原语管理状态，`VguiRoot` 将二者接入 GPUI 窗口。

## 主要组成部分

| 部分 | 职责 |
| --- | --- |
| `vgui` | 提供挂载、响应式、控制流、组件、样式和公开宏。 |
| `vgui-view` | 解析 `view!` 标记和 `#[vgui_component]`，生成 Rust 代码与 GPUI 构建器表达式。 |
| `VguiRoot` | 作为 GPUI entity，持有根渲染闭包和响应式作用域。 |
| `Scope` | 保存位置式响应式 slot、订阅、memo、effect、清理回调和子作用域。 |
| GPUI | 提供元素、entity、窗口、事件和原生渲染。 |

应用通常通过 `vgui::prelude::*` 导入常用 API。宏由 `vgui` 重新导出，因此应用代码不需要直接调用过程宏 crate。

## 跟踪一次渲染

[快速开始](../quick-start/)使用以下回调挂载应用：

```rust
|window, cx| vgui::mount(window, cx, app)
```

`mount` 创建 `VguiRoot`，并将 `app` 保存为渲染闭包。每次 GPUI 渲染会执行以下步骤：

1. 重置根作用域及其后代作用域的位置式 slot 游标。
2. 进入响应式作用域，从头调用 `app`。
3. 计算 signal 读取、组件调用以及 `view!` 中的表达式。
4. 构建新的 GPUI 元素树，然后离开响应式作用域。
5. 将元素树交给 GPUI 进行布局、绘制和事件分发。

标记在编译期展开。vgui 不会在运行时解析 HTML，也不会创建浏览器 DOM 节点。

## 写入之后发生什么

值发生变化时，`WriteSignal::set` 和 `WriteSignal::update` 会更新 GPUI entity。它的观察者随后要求 `VguiRoot` 处理该依赖：

1. 已记录的依赖集中包含此 entity 的 memo 和 effect 会运行。
2. 值发生变化的 memo 会通知自己的依赖方。
3. `cx.notify()` 请求重新渲染已挂载的根视图。
4. 根渲染闭包再次运行，构建新的元素树。

这是**根视图重新渲染，而不是虚拟 DOM diff**。memo 和 effect 能避免部分重复计算，但 vgui 不会单独更新某个文本节点，也不会协调两棵虚拟树。即使 store 的选中切片没有变化，store 写入也会请求根视图重新渲染。

读取、写入、memo、effect 和 store API 请参阅[响应式](../reactivity/)。

## 为什么重新渲染后状态仍然存在

调用 `create_signal`、`create_store`、`create_memo`、`create_effect` 或 `on_cleanup` 会消耗当前作用域的下一个 slot。首次渲染时，vgui 创建并保存原语；后续渲染会在相同位置和类型上取回已有原语，而不会重新应用初始值。

因此，多次渲染之间必须保持响应式原语的创建顺序和类型稳定。不要有条件地创建原语、调整其顺序，或将其放入长度可变的循环。某个位置上的 slot 种类或类型发生变化，或者初始化后使用的 slot 数量不同，都会产生错误。

`view!` 还会根据调用顺序为有状态元素生成确定性的元素 ID。有状态组件的 entity 可以缓存在 slot 中，使编辑或焦点等 GPUI 状态在周围元素树重建后仍然保留。

## 为条件和列表项状态使用子作用域

部分控制流元素会创建具有独立 slot 序列的子作用域：

- `<Switch>` 中每个活跃的 `<Match>` 分支都有分支局部作用域。离开分支时会释放该作用域。
- `<Index>` 的每个位置都有列表项局部作用域。列表缩短时，超出新长度的作用域会被释放。
- 释放作用域会运行已注册的 `on_cleanup` 回调，清除订阅和 slot，并先释放子作用域再释放父作用域。

`<Index>` 作用域属于**位置**，不属于稳定的列表项 key。因此重新排序列表项时，其局部状态不会随列表项移动。`<Show>` 和 `<For>` 不创建子作用域；不要在按条件执行的 `<Show>` 主体或长度可变的 `<For>` 行中创建位置式响应式原语。

[控制流](../control-flow/)介绍如何选择这些结构，[自定义组件](../custom-components/)则说明为什么组件调用会共享调用方作用域，除非当前已进入上述某个子作用域。

## 选择状态的归属位置

根据需要的状态生命周期决定放置位置：

- 将应用级或共享视图状态放在根渲染路径中。
- 将分支局部的草稿或订阅放在 `<Match>` 分支内。
- 将位置局部的行状态放在 `<Index>` 行内。
- 将无状态标记放在普通函数和组件中。

要继续了解生成元素树的语法，请阅读 [`view!` 宏](../view-macro/)。原生与 WebAssembly 的边界请参阅[原生与 Web](../native-and-web/)。
