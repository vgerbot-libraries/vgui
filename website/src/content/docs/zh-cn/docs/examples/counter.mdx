## 跟踪响应式更新

1. `create_signal(0i32)` 返回 `count` 读取句柄和 `set_count` 写入句柄。
2. 构造标签时，`count.get()` 读取当前整数。在响应式渲染作用域中，这次读取会建立视图对 signal 的依赖。
3. `click` 将闭包适配为 GPUI 点击监听器。闭包通过应用上下文调用 `set_count.update`，原地递增整数。
4. signal 的值变化后，vgui 会通知依赖方并请求重新渲染已挂载的根视图。下一次渲染读取新的计数并构造更新后的标签。

signal 在已挂载的响应式视图中创建，而不是在入口函数中创建。重复渲染会复用它的位置式状态，不会把计数重置为零。请在多次渲染之间保持响应式原语的创建顺序和类型稳定。

写入经 `PartialEq` 比较后相等的值不会触发 signal 通知。这与[Store 与列表](../store-and-lists/)中介绍的 store 行为不同。

## 原生与 WASM 入口

共用的 `run` 函数在原生目标上创建 `application()`，在 WASM 上创建 `single_threaded_web()`。其中的 `launch` 闭包负责打开窗口，并通过 `vgui::mount` 挂载 `app`。原生 `main` 调用 `gpui_app.run(launch)`；WASM 的 `#[wasm_bindgen(start)]` 函数调用 `web_init()`、安装键盘事件拦截，并使用 `run_embedded`。由于 WASM 启动是非阻塞的，`std::mem::forget` 会保留返回的应用句柄。

在仓库根目录运行原生计数器：

```sh
cargo run -p vgui --example counter
```

在仓库根目录生成预编译 WASM 资源并构建网站：

```sh
npm run build --prefix website
```

## 样式

`class` 属性使用 vgui 支持的 Tailwind 风格工具类为 GPUI 元素设置样式。根元素的 `w-full h-full` 使其填满原生窗口或浏览器 canvas，而不是使用固定尺寸。这些类不需要浏览器样式表，标记也不会创建浏览器 DOM 节点。
